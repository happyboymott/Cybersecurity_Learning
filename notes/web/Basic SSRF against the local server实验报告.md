# Basic SSRF against the local server实验报告

## 目标:
温习ssrf相关的利用

## 环境:
本次实验环境来自portswigger Web Security Academy靶场，关卡Basic SSRF against the local server，难度APPRENTICE，使用工具为bp

## 步骤:
1. 进入靶场，发现是一个电商网站

![靶场主界面](../images/屏幕截图%202026-11-18%20102754.png)

2. 尝试直接访问管理后台，发现存在鉴权，但是其中提示可以通过回环地址请求，考虑使用ssrf进行操作

![直接访问管理后台提示权限问题](../images/屏幕截图%202026-11-18%20110646.png)

3. 进入商品页面，发现有一个查看库存的功能点，考虑其为ssrf入口

![商品主页面](../images/屏幕截图%202026-11-18%20103205.png)

4. 抓到查询库存的数据包，发现关键参数stockApi,尝试通过此参数访问管理后台

![查询库存数据包](../images/屏幕截图%202026-11-18%20103223.png)

![修改后的查询数据包](../images/屏幕截图%202026-11-18%20103241.png)

5. 数据包发出后，成功访问到后台管理界面，进一步抓取删除用户的数据包

![后台管理界面](../images/屏幕截图%202026-11-18%20103251.png)

![删除用户数据包](../images/屏幕截图%202026-11-18%20113538.png)

6. 考虑到所有后台均存在鉴权，继续使用stockApi参数进行删除用户操作

![修改后用于删除用户的数据包](../images/屏幕截图%202026-11-18%20104531.png)

7. 成功发包删除用户，实验完成

![实验完成截图](../images/屏幕截图%202026-11-18%20104539.png)

## 结论:
此实验环境的漏洞成因为在stockApi参数上缺乏有效过滤，配合本地回环访问无鉴权的情况，攻击者只需简单修改查询库存的数据包就可以直接使用后台功能，修复方向为针对stockApi参数添加充分的过滤，同时保持全环节的鉴权操作
